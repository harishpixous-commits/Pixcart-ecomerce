# From zero to live: step-by-step

This is the one guide to follow, in order, from a fresh AWS account to a live marketplace. It is written so
that a person or an AI agent can follow it without other context. Each step says **who** does it, **where**,
and **how to check it worked**. The admin panel has the same list with live ticks at **Admin → Go-live checklist**.

> Nothing in the code needs editing to launch. Business details, payment/SMS/email/shipping/AI keys, tax rates,
> roles, AI models and storefront content are all entered in the admin panel. Only the domain and AWS account
> go into Terraform.

---

## 1. Try it on your computer (optional, 15 minutes)

```bash
docker compose up --build            # opens http://localhost:3000 with demo data
# Admin: http://localhost:3000/admin/login  admin@pixcart.in / PixCart@Admin2026 (local only)
```

To try online payments without internet access or a Razorpay account, run the **Razorpay simulator**
(`tools/razorpay-sim/sim.py`, instructions at the top of the file) and point the API at it. Then
`python tools/razorpay-sim/smoke.py` runs order → payment → webhook → cancel → refund and prints ✓ for each step.

## 2. Create the staging servers (Terraform, ~40 minutes, once)

**Who:** whoever has AWS admin access. **Where:** a terminal with AWS CLI, Terraform ≥ 1.10 and Docker.

1. Create an S3 bucket for Terraform state (versioning on), e.g. `yourshop-terraform-state`.
2. ```bash
   cd infra/terraform
   cp backend.hcl.example backend-staging.hcl     # set key = "pixcart/staging.tfstate"
   cp staging.tfvars.example staging.tfvars       # set domain, hosted_zone, media_domain, github_repository, alarm_email
   terraform init -backend-config=backend-staging.hcl
   terraform apply -var-file=staging.tfvars -target=aws_ecr_repository.repo
   ```
3. Push a first pair of images (the services need one to start):
   ```bash
   aws ecr get-login-password | docker login --username AWS --password-stdin <account>.dkr.ecr.ap-south-1.amazonaws.com
   docker build -t <ecr_api>:latest ../../backend && docker push <ecr_api>:latest
   docker build --build-arg API_ORIGIN=http://api:8000 -t <ecr_web>:latest ../../frontend && docker push <ecr_web>:latest
   terraform apply -var-file=staging.tfvars
   ```
4. Confirm the CloudWatch alarm email AWS sends you.
5. Note the outputs: `site_url`, `ecs_cluster`, `private_subnets`, `app_security_group`, `deploy_role_arn`,
   `outbound_ip` (for RazorpayX), `webhook_urls`.

JWT secret, encryption key and database password are generated by Terraform into AWS Secrets Manager.
**You never type or see them.**

**Check:** `https://staging.yourshop.in/api/health` returns `{"status":"ok"}`.

---

## 3. Connect GitHub so every change deploys itself (~10 minutes, once)

1. GitHub → Settings → Environments → create **staging** (and later **production**).
2. Add variables from the Terraform outputs: `AWS_DEPLOY_ROLE_ARN`, `AWS_REGION` (ap-south-1), `ECS_CLUSTER`,
   `PRIVATE_SUBNETS`, `APP_SECURITY_GROUP`.
3. Actions → **Deploy** → Run workflow → target **staging**. It builds, runs database migrations as a one-off
   task, rolls out API then web, and runs a smoke test. A failed rollout rolls back by itself.

**Check:** the workflow is green; the shop opens at your staging domain.

## 4. Create the first admin (5 minutes, once)

```bash
aws ecs execute-command --cluster <ecs_cluster> --task <api-task-id> --container api --interactive \
  --command "python -m scripts.seed"          # categories only (never --demo on a real server)
aws ecs execute-command ... --command "python -m scripts.create_admin --email you@yourshop.in --name 'Your Name'"
```

Sign in at `/admin/login` → **My account** → turn on **two-step sign-in**.

## 5. Set everything up in the admin panel (~1 hour)

Every key is encrypted before it is saved and never shown again. Saving keys asks for your password
(and your authenticator code). Each integration has a **Test connection** button.

| # | Admin page | What to enter | Check |
|---|---|---|---|
| 5.1 | **Storefront → Business, contact and social** | Legal name, e-commerce operator GSTIN, registered address, grievance officer (name, email, phone), customer-care contacts, social links | `/contact` and the footer show them |
| 5.2 | **Storefront → Brand** | Brand name, logo, colours, Google Analytics / Meta Pixel IDs (optional) | Shop header changes at once |
| 5.3 | **Storefront → Pages** | Paste the lawyer's Terms, Privacy notice, Returns policy | Pages open without "placeholder" text |
| 5.4 | **Settings** | Fees, COD limits, the days damaged, faulty or wrong items can be returned, and the tax rates your CA confirmed. Each category's return window and minimum are in **Categories** | — |
| 5.5 | **Integrations → Razorpay payments** | **Test** Key ID + Key secret; webhook secret. In Razorpay Dashboard → Webhooks add the webhook address shown on the page with the listed events | Test connection: "Connected to Razorpay in test mode". After the first test payment, "Last received" under the webhook address shows the time: the webhook works |
| 5.6 | **Integrations → MSG91 SMS** | Auth key, OTP template ID (DLT approved), sender ID; switch on | Test with your mobile → SMS arrives |
| 5.7 | **Integrations → Email** | SES SMTP user/password, sender address on your verified domain | Test → email arrives |
| 5.8 | **Integrations → WhatsApp / Shiprocket / Sentry** | Optional | Test connection |
| 5.9 | **Integrations → RazorpayX** (optional) | Account number + webhook secret; allowlist `outbound_ip` in RazorpayX | Test connection |
| 5.10 | **AI providers** | Add Claude (or OpenAI, Gemini, Groq, …); add 2+ keys and a fallback provider if you like; set routes | Test → "OK in … ms" |
| 5.11 | **AI assistant** | Name, house rules, decision layer (built-in rules is fine), voice languages | "Try" shows the decision |
| 5.12 | **Staff and roles** | Edit roles or create your own; add staff | Staff sign in and see only their pages |
| 5.13 | **Languages and currencies** | Currencies shoppers can pick (rates typed or updated daily), charge in rupees or in the shopper's currency (needs Razorpay international payments), languages, country rules, ways to pay, card logos, saved cards | The shop footer shows "Pay with" logos and the language and currency picker; Tamil and Hindi work for the main screens at once, other lines once an AI model is on the "Translating the site" route |

## 6. Test staging like a customer (~1 hour)

Do each and tick it. Use Razorpay **test** cards: `4111 1111 1111 1111`, any future expiry, any CVV, OTP as shown; UPI `success@razorpay`.

- [ ] Sign up on the shop with your mobile (real OTP SMS arrives).
- [ ] Register as a seller, upload KYC; approve in Admin → Sellers; add a product; approve it in Admin → Listings.
- [ ] Buy it with **online payment**: the Razorpay window opens, pay, order shows "Payment received" with the Razorpay reference.
- [ ] On a **phone** (and in the Android app): pay by UPI (test UPI `success@razorpay`, or the UPI app list on a real phone). After paying you come back to the order and see "Payment received". Use `failure@razorpay`: you see "Payment not received", the reason, and **Try again**.
- [ ] Pick another currency in the footer: prices change; checkout says what you will pay (₹, or the currency when charged in it). Pay by card and tick "Save this card": Account → Saved cards lists it (last 4 digits only); remove it.
- [ ] Pick Tamil or Hindi: the shop, seller hub, delivery app and admin show in it; correct a line under Admin → Languages and currencies → Translations.
- [ ] Admin → Orders → an online order → **Check payment with Razorpay** answers (for an order a shopper says they paid but that still waits for payment).
- [ ] Razorpay Dashboard → Webhooks shows deliveries with status 200.
- [ ] Seller confirms, packs, ships (Shiprocket or manual AWB), marks delivered; invoice PDF opens.
- [ ] Return the item; seller approves and receives; refund appears in Razorpay → Refunds.
- [ ] Buy with **cash on delivery**; cancel before shipping.
- [ ] Emails/SMS arrive for order placed, shipped, delivered, refund.
- [ ] Admin → Payouts → Run payouts (bank file or RazorpayX test payout).
- [ ] Admin → Exports: download Excel, PDF and a ZIP of several reports.
- [ ] Open the assistant (Ctrl+J): "How much did we sell today?", "export last week's orders as Excel",
      attach a CSV and ask it to compare with live orders, try voice mode.
- [ ] Admin → Go-live checklist: only "live keys" items remain.

## 7. Production (~1 hour)

1. Same as step 2 with `backend.hcl` (key `pixcart/production.tfstate`) and `terraform.tfvars` (your real
   domain, `db_multi_az = true`). Run `terraform apply`.
2. GitHub environment **production** with the production outputs. From now on, every push to `main` that passes
   CI deploys to production; deploy to staging first with the manual workflow.
3. Step 4 (first admin, two-step sign-in) and step 5 again on production — with **live** Razorpay keys
   (after KYC), live MSG91, SES out of the sandbox.
4. Place a real ₹1 order (create a ₹1 product, approve it), pay with your own card/UPI, then cancel to check the refund.
   Delete the product afterwards.
5. **Admin → Go-live checklist** shows "Ready to launch". Announce.

## 8. After launch

| What | Where |
|---|---|
| Errors | Sentry (if connected) and CloudWatch Logs `/ecs/<name>-api` |
| Alarms (5xx, CPU, database) | Email from CloudWatch |
| Backups | RDS automated snapshots (7 days); restore a snapshot to a new instance once to practise |
| Who changed what | Admin → Audit log (every key change, role change, export and assistant action) |
| AI cost | Admin → AI studio (monthly budget, usage, estimated cost) and your provider's console |
| Rotate a key | Paste the new one in Admin → Integrations or AI providers; no redeploy needed |
| New release | Push to `main`; or Actions → Deploy → staging first, then production |

## 9. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| "Online payment is not available" at checkout | Razorpay switched off or keys missing | Admin → Integrations → Razorpay: switch on, Test connection |
| Orders stay "awaiting payment" after paying | Webhook not reaching the server, or wrong webhook secret | Razorpay Dashboard → Webhooks → deliveries; re-enter the secret in both places. Meanwhile Admin → the order → **Check payment with Razorpay** records it (the shopper's order page also checks by itself) |
| On phones, shoppers land back on a blank or old page after paying in a UPI app | The phone's browser reloaded the page | Nothing to fix: the order page asks Razorpay and shows the result. To keep the payment window on the same page instead, Admin → Marketplace settings → Orders and payouts → "After paying in a UPI app" |
| The Android app does not open Google Pay / PhonePe | App built before this change | Build the app again (Actions → Android shop app) and upload the new APK |
| "Sign-in by OTP is not set up yet" | MSG91 not switched on (production never prints OTPs to logs) | Admin → Integrations → MSG91 |
| Test connection says "cannot reach the provider" | No outbound internet from the tasks | Check the NAT gateway and security group egress (Terraform) |
| RazorpayX payouts fail with an IP error | Server IP not allowlisted | Allowlist Terraform output `outbound_ip` in RazorpayX |
| Assistant says "Sandbox mode" | No AI model connected | Admin → AI providers → add a connection and a route |
| "None of the connected AI models answered" | All keys rate-limited or out of credit | Add another key or a fallback provider in AI providers |
| Voice button missing | Role lacks `assistant_voice`, voice off, or browser without speech recognition | Staff and roles; AI assistant → Voice; use Chrome or Edge |
